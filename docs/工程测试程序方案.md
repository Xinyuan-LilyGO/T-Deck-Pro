# `examples/eng_test` 工程测试程序方案

## Summary
- 在 `examples/` 下新增独立入口 `examples/eng_test`，专门用于工程验收/硬件快测；`examples/factory` 保持不动，继续作为现有演示和调试程序。
- UI 采用中文优先的黑白 EPD 测试界面，主流程为“引导式顺序测试”，同时保留“深度验证”入口，满足“快速验收 + 外部链路深测”两层需求。
- 支持“部分模块未搭载”的场景：开测前由人工勾选未装模块，这些项目在本次会话中自动跳过；测试过程中每页仍保留临时 `Skip`。
- 结果同时显示在屏幕和串口；人工项明确记录 `PASS/FAIL`；所有未测项目统一记为 `SKIP`。

## Implementation Changes
- 架构：新增一个轻量测试框架，定义统一的 `TestCaseId`、`TestStatus`、`TestMode`、`TestCaseDescriptor`，每个测试项按 `setup / poll / render / handle_input / teardown` 回调组织。
- 状态模型：使用 `NOT_RUN / RUNNING / PASS / FAIL / SKIP` 五态；不再区分“未安装”和“人工跳过”，两者统一归入 `SKIP`，但串口日志可附带原因文本用于排查。
- 预配置流程：开机进入“模块选择页”，列出可测模块，默认全选；操作员取消勾选未搭载模块后进入正式测试。未选模块从顺测流程中直接按 `SKIP` 记录并跳过执行。
- 运行时流程：每个测试页固定提供 `Pass / Fail / Retry / Skip / Next` 控件；已设为未安装的模块默认不进入测试页，运行时 `Skip` 主要用于异常工况或当前无法验证的项目。
- 复用策略：`v1` 不做 repo 级公共层重构，直接在 `examples/eng_test` 内复制/裁剪 `factory` 中已稳定的板级初始化、触摸适配、外设封装和 EPD/LVGL 刷新逻辑，优先保证交付速度。
- 硬件调度：测试运行器统一管理 XL9555 电源域、A7682E/ES8311 音频切换、功放开关，以及 EPD/SD/LoRa 共用 SPI 的片选互斥；默认只在测试当前模块时打开对应电源，减少互扰。
- 页面结构：包含“模块选择页”“开机自检页”“Quick Test 顺测页”“Deep Diagnostics 深测菜单”“Final Summary 汇总页”“Sleep Resume 唤醒恢复页”；页面切换用全刷，状态更新用局刷。

## Interfaces And Test Items
- 对外新增的核心接口只限于测试程序内部：测试注册表、测试运行器、结果记录器、模块使能位图、RTC/NVS 恢复状态结构，不改现有板级公共接口。
- 模块选择页支持以下条目启用/禁用：EPD、Touch、Keypad、GPS、ES8311、Battery、Motor、IMU、Wi‑Fi、SD、A7682E、LoRa、BLE、Sleep。
- Quick Test 必测项：
  - 显示：黑/白/反相图案 + 局刷区域计数，人工确认无花屏、无坏线、局刷正常。
  - 触摸：四角加中心靶点，全部命中后自动通过。
  - 键盘：快测只要求按下一组覆盖全部行列的代表键；完整矩阵验证放到深测页。
  - 电池：初始化 SY6970/BQ27220，读取电压、电量、充电状态，并校验值在合理范围内。
  - SD：挂载、创建临时文件、读回校验、删除临时文件。
  - 音频：切到 ES8311 路径并打开功放，播放内置 WAV，人工确认能听到声音。
  - 马达：顺序播放 2-3 个震动效果，人工确认有明显震动。
  - IMU：提示操作员倾斜设备，检测姿态/陀螺变化超过阈值后自动通过。
  - Wi‑Fi：完成一次扫描调用并显示 AP 数量；扫描成功但结果为 0 不判失败。
  - GPS 基础：确认模块上电、UART 正常，并在超时内收到 NMEA/UBX 活动。
  - 4G 基础：A7682E 上电并收到 `AT` 响应；`CPIN`、`CSQ` 只做信息展示，不作为快测通过前提。
  - LoRa 基础：SX1262 初始化、参数下发、发送完成中断正常。
  - BLE 基础：启动固定测试广播，并完成一次扫描启动/停止，只验证 BLE 栈和基本能力。
  - Sleep：把测试进度写入 RTC/NVS，进入深睡眠；唤醒后识别唤醒原因并恢复到汇总页，标记该项通过。
- Deep Diagnostics 深测项：
  - GPS：卫星数、时间、经纬度、速度和 fix 状态。
  - 4G：SIM 状态、信号、注册状态、AT 控制台、可选拨号/通话测试。
  - LoRa：与对端板卡进行收发联调并显示 RSSI/SNR。
  - BLE：显示周边扫描结果，并提示手机验证固定广播名和广播数据。
  - 音频：增加 SD WAV 播放和音频路径切换测试。
  - 键盘：完整矩阵键位验证。
  - Shutdown：作为单独的 destructive test，不放进默认快测闭环。

## Test Plan
- 在 PlatformIO 中新增可选 `src_dir = examples/eng_test`，先不替换当前默认 `examples/factory`，待新程序稳定后再决定是否切换默认入口。
- 验证“模块选择页”能正确影响顺测流程，未勾选模块不会执行初始化/动作测试，并在最终汇总中记为 `SKIP`。
- 验证快测流程可在正常样机上 3 分钟内完成，且不要求手机、LoRa 对端、室外 GPS fix 或蜂窝注册环境。
- 验证每个测试项都输出串口开始/结束日志，最终汇总包含总数、通过数、失败数、跳过数以及失败/跳过项列表。
- 验证睡眠测试后的状态恢复，确保唤醒后不会丢失先前测试结果。
- 回归验证共享硬件约束：EPD/SD/LoRa SPI 互斥、触摸复位走 XL9555、音频路由切换正确、A7682E 仅在电池接入时进入正式测试。

## Assumptions
- `v1` 以中文操作界面为主，串口日志保持稳定、简洁、便于后续接自动化采集工具。
- `factory` 保留为旧的演示/调试程序，`eng_test` 专注工程验收；本轮不做大范围共享代码抽取。
- 未搭载模块由人工在开测前取消勾选；本次会话内该选择保持有效，不要求跨重启长期保存。
- A7682E 基础测试默认要求电池接入；GPS 深测默认要求室外或良好天空视野；LoRa 深测需要第二台设备；BLE 深测默认可借助手机完成外部可见性验证。
- 关机测试不纳入默认快测通过条件，因为它会中断本次会话；休眠测试纳入默认快测，因为可以唤醒恢复并自动续跑。
